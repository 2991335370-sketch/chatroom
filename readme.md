# AI 协作聊天室工程训练 — 第一周可运行项目 (V1)

本项目是《四周 AI 协作聊天室工程训练：学生任务书》**第一周任务包（让多人聊天真正跑起来）**的完整实现与文档交付仓库。
采用教材推荐技术路线：**浏览器页面 + Python/FastAPI + WebSocket**，支持同局域网多设备通过浏览器实时双向广播聊天。

## 2. 环境要求与安装依赖

* **Python 版本**：Python 3.9 及以上（推荐 Python 3.10 / 3.11）
* **网络条件**：所有参与联调的电脑或手机接入同一个 Wi-Fi 路由器或同一个手机个人热点。
* **安装依赖**：

```bash
pip install -r requirements.txt
```

## 3. 启动服务器（任务 1.4 & 1.5）

在充当服务器的电脑上进入项目目录，执行以下任一命令启动服务：

```bash
# 方式一：直接运行 main.py（自动绑定 0.0.0.0:8000 并打印本机局域网 IP）
python3 main.py

# 方式二：使用 uvicorn 命令行启动（务必加上 --host 0.0.0.0 以允许局域网设备访问）
uvicorn main:app --host 0.0.0.0 --port 8000 --ws wsproto
```

启动成功后，终端会输出类似如下日志证据：

```text
============================================================
AI 协作聊天室 V1 启动中 (监听 0.0.0.0:8000)
1. 本机浏览器自测地址: http://127.0.0.1:8000
2. 同局域网其他设备访问地址: http://192.168.1.100:8000
============================================================
INFO:     Uvicorn running on http://0.0.0.0:8000 (Press CTRL+C to quit)
```

## 4. 多设备访问与验收步骤（任务 1.5 & 1.6）

1. **服务器本机自测（设备 A）**：
   * 打开浏览器访问 `http://127.0.0.1:8000`（或 `http://<服务器局域网IP>:8000`）。
   * 页面顶部状态栏显示 `已连接 (OPEN)`。
2. **第二台/第三台设备接入（设备 B、设备 C）**：
   * 确保设备 B（另一台电脑或手机）与服务器连接**同一个 Wi-Fi 或手机热点**。
   * 在设备 B 的浏览器地址栏输入服务器终端打印的局域网地址（例如 `http://192.168.1.100:8000`，**切勿在设备 B 上输入 `127.0.0.1`**）。
   * 设备 B 无需复制任何代码，直接打开网页即可看到 `已连接 (OPEN)`。
3. **双向广播验收（任务 1.6 验收场景）**：
   * 在设备 A 输入 `hello from A` 并点击发送，设备 A 与设备 B 页面均实时显示 `[HH:MM:SS] hello from A`。
   * 在设备 B 输入 `hello from B` 并点击发送，设备 A 与设备 B 页面均实时显示 `[HH:MM:SS] hello from B`。
   * 加入第三个浏览器（设备 C），三方发送消息均能实时同步显示。

## 5. 一键运行自动化验收脚本

仓库提供了 `verify_v1.py`，可自动验证任务 1.4 的 6 个检查点、任务 1.6 的三客户端（A、B、C）广播验收场景以及异常断开自动清理：

```bash
python3 verify_v1.py
```

## 6. 常见启动与联调问题排查（任务 1.5 调试顺序）

1. **第二台设备打不开页面（连接超时 / 拒绝连接）**：
   * **第 1 步（确认同一网络）**：检查两台设备是否连在同一个 Wi-Fi/手机热点下（注意校园网可能开启 AP 隔离，遇此情况请改用手机热点）。
   * **第 2 步（确认监听地址）**：检查服务器启动命令是否包含 `--host 0.0.0.0`。若只写了 `127.0.0.1`，外部设备一律无法连入。
   * **第 3 步（确认访问地址）**：确认第二台设备浏览器输入的是**服务器电脑的局域网 IP**（如 `http://192.168.1.100:8000`），而不是 `0.0.0.0` 或 `127.0.0.1`。
   * **第 4 步（检查防火墙）**：若仍无法访问，临时放行服务器电脑的 TCP `8000` 端口或关闭系统防火墙重试。
2. **页面能打开，但状态一直显示“已断开”无法发消息**：
   * 打开浏览器 `F12 -> Console / Network` 查看 WebSocket 连接地址。本项目已采用 `window.location.host` 动态拼装 `ws://<当前访问地址>/ws`，若自行修改过前端代码，请检查是否误将地址写死为 `ws://127.0.0.1:8000/ws`。
