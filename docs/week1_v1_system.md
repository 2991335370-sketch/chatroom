# 第一周聊天室 V1 保姆级实操使用教程 (`week1-tutorial.md`)

这份教程带你从零开始，把我们生成的 6 个文件在本地电脑上跑起来，完成**本机测试、手机/第二台电脑局域网联调、自动化验收脚本运行**以及 **Git 仓库提交**。

## 第一步：在本地电脑整理项目文件夹

在你的电脑桌面（或任意工作目录）新建一个文件夹，命名为 `chatroom-v1`，并把画布（Canvas）中的文件按以下目录结构保存进去：

```
chatroom-v1/
├── main.py                      # 服务端与网页主程序
├── verify_v1.py                 # 自动化验收测试脚本
├── README.md                    # 项目启动说明
└── docs/                        # 新建一个 docs 子文件夹，放入下面 3 个文档
    ├── week1-team.md            # 任务 1.1 小组分工表
    ├── week1-concepts.md        # 任务 1.2 & 1.3 消息链路与概念地图
    └── week1-v1-system.md       # 任务 1.7 & 1.8 V1 系统说明与故障记录

```

## 第二步：安装 Python 依赖包

1. 打开终端（Windows 用户打开 **PowerShell** 或 **CMD**；Mac 用户打开 **终端 Terminal**）。

2. 进入你刚才创建的 `chatroom-v1` 文件夹：

```
cd 你的路径/chatroom-v1

```

3. 安装运行所需的依赖包（如果电脑同时装了 Python 2 和 Python 3，请用 `pip3`）：

```
pip install fastapi uvicorn wsproto httpx

```

> **国内网络加速小贴士**：如果下载慢，可以加上清华镜像源：
> `pip install -i https://pypi.tuna.tsinghua.edu.cn/simple fastapi uvicorn wsproto httpx`

## 第三步：一键跑通自动化验收脚本（验证代码无误）

在启动浏览器之前，你可以先运行我们写好的自动化验收脚本 `verify_v1.py`，它会自动帮你模拟 A、B、C 三个浏览器连接并互发消息：

```
python verify_v1.py
# 如果是 Mac / Linux，使用：
python3 verify_v1.py

```

只要看到终端最后输出：
`结论：第一周 V1 全部检查点（1.4 ~ 1.8）自动化验收 100% 通过！`
就说明你的 Python 环境和服务端代码已经完全正常。

## 第四步：启动聊天室服务器（任务 1.4）

在终端中运行以下命令启动聊天室服务：

```
python main.py
# 或者用 uvicorn 命令启动：
uvicorn main:app --host 0.0.0.0 --port 8000 --ws wsproto

```

启动成功后，不要关闭这个终端窗口，你会看到类似下面的提示（注意看第 2 行的局域网地址）：

```
============================================================
AI 协作聊天室 V1 启动中 (监听 0.0.0.0:8000)
1. 本机浏览器自测地址: http://127.0.0.1:8000
2. 同局域网其他设备访问地址: http://192.168.1.100:8000
============================================================
INFO:     Uvicorn running on http://0.0.0.0:8000 (Press CTRL+C to quit)

```

## 第五步：单机多窗口自测（先在自己电脑上试）

1. 在运行服务器的这台电脑上，打开浏览器（Chrome / Edge / Safari），地址栏输入：
   `http://127.0.0.1:8000`

2. 观察页面顶部状态栏，会显示绿色的 **`已连接 (OPEN)`**。

3. **模拟多人聊天**：再新开第 2 个、第 3 个浏览器标签页（同样打开 `http://127.0.0.1:8000`）。

4. 在第 1 个标签页输入 `hello from A` 并按回车（或点击“一键发送测试消息”），你会看到 3 个标签页**同时实时弹出**带时间戳的 `[HH:MM:SS] hello from A`；同时回到终端窗口，能看到清晰的 `[EVENT=CONNECT]`、`[EVENT=MESSAGE]`、`[EVENT=BROADCAST_DONE]` 日志。

## 第六步：手机或第二台电脑局域网联调（任务 1.5 & 1.6 核心验收）

课堂验收要求“至少两台不同设备通过浏览器进入页面并互相看到实时消息”，操作步骤如下：

1. **连同一个网络（最稳妥推荐：开手机热点）**：

   * 校园网或公共 Wi-Fi 往往开启了“AP 隔离”（禁止设备互访）。

   * **最稳妥做法**：用你的手机开启“个人热点”，让运行服务器的笔记本电脑连上你手机的热点（此时手机和电脑就在同一个局域网里了，或者让队友的电脑也连这个热点）。

2. **查看服务器的新局域网 IP**：

   * 连上热点后，在电脑终端按 `Ctrl + C` 停止服务，再重新运行 `python main.py`。

   * 看终端打印出的第 2 行地址（例如 `http://172.20.10.2:8000` 或 `http://192.168.43.10:8000`），或者看电脑浏览器页面蓝色提示框里显示的地址。

3. **在第二台设备（手机或队友电脑）打开网页**：

   * 打开手机自带浏览器（或队友电脑浏览器），在地址栏输入刚才看到的局域网地址（例如 `http://172.20.10.2:8000`）。

   * **注意**：手机或队友电脑上**千万不要输 `127.0.0.1:8000`**，一定要输服务器的局域网 IP！

4. **双向发消息验收**：

   * 电脑发一句 `hello from PC`，手机发一句 `hello from Phone`，两边屏幕实时同步显示，即宣告第一周核心任务通关！

## 第七步：如果手机/第二台电脑打不开页面怎么办？（30 秒排障）

如果电脑自己能打开 `127.0.0.1:8000`，但手机输入局域网 IP 一直转圈打不开，99% 是 **Windows 防火墙拦截了 8000 端口**：

* **Windows 快速放行方法**：

  1. 打开 Windows 搜索框，搜索并打开 **“允许应用通过 Windows 防火墙”**（或“高级安全 Windows Defender 防火墙”）。

  2. 在聯调演示期间，可以临时将 **“专用网络 / 公用网络”的防火墙关闭**，或者新建一条入站规则放行 TCP `8000` 端口。

  3. 放行后手机刷新页面即可秒开。

## 第八步：个性化修改文档并提交 Git 版本节点（任务 1.1 & 1.8）

1. **替换你们小组的真实信息**：

   * 打开 `docs/week1-team.md` 和 `docs/week1-v1-system.md`，把里面的示例名字（`赖陶一、张唯涵、杨朗、吴芳芳`）和同步时间替换成你们组员的真实姓名。

2. **生成符合教材要求的 Git 提交记录与 `v1.0` 标签**：
   在 `chatroom-v1` 文件夹终端依次执行以下命令，即可生成老师检查时最规范的提交历史：

```
git init
git add docs/week1-team.md docs/week1-concepts.md
git commit -m "docs(week1): 完成任务1.1组队分工与任务1.2-1.3消息链路和概念地图"

git add main.py README.md
git commit -m "feat(v1): 实现FastAPI+WebSocket多设备局域网广播聊天室(任务1.4-1.6)"

git add verify_v1.py docs/week1-v1-system.md
git commit -m "test(v1): 添加自动化验收脚本并完成V1系统说明与故障记录(任务1.7-1.8)"

git tag -a v1.0 -m "Week 1 V1 Milestone"

```

如果需要推送到 GitHub / Gitee 供全组访问，只需在 GitHub/Gitee 新建一个空仓库，然后执行：

```
git remote add origin <你们的远程仓库地址>
git push -u origin master --tags

```
